# 真实商品数据导入工程 — 老板视角的 7 步链路

> 把"真实淘宝商品标题库"清洗、归一化、入库到 ai-cs-agent 商品知识库 + RAG 向量库，让系统在真实语料上跑起来。

## 一、目标与背景

ai-cs-agent 原本只有 5 条 demo 商品（OVERVIEW + 4 商品 P1001-P1004）和 7 条 demo 店铺政策，向量库只有 23 个 chunk。真实工程链路下，需要：

1. 拿一份**真实的、原始的、字段不完整**的商品数据
2. 模拟"老板把商品信息导入知识库"的工程链路 — 含数据清洗、字段映射、批量入库
3. 把真实语料编入 RAG 向量库，让检索在真实规模上跑起来

## 七、已知问题与环境备注

### chromadb 1.5.9 hnsw 损坏

**问题**：`pip install chromadb` 默认装到 1.5.9 版本，在 Windows 上 `build_index` 后，hnsw segment 文件未正确生成，导致后续 `collection.count()` / `.get()` / `.query()` 全部抛 `Error loading hnsw index`。

**已验证**：数据完整写入 `chroma.sqlite3`（1327 行 embeddings 元数据），可通过 SQL 读出 documents/metadatas。

**绕过方案**：`scripts/verify_rag_search.py` 直接读 sqlite + 用 bge embedder 算 cosine，验证 RAG 检索逻辑。检索行为与 chromadb hnsw 等价（都是 cosine top-k）。

**后续修复路径**（按工作量排序）：

1. **降级 chromadb 到 0.4.24** — 已尝试 3 次，pip 在 Windows safe-delete 反复撞 `.exe` 文件锁（`SHFileOperationW 失败: 0x2`）。需先手动清空 `.venv/Scripts/` 下所有非核心 `.exe`，再 force-reinstall。已记录此坑。
2. **改用 FAISS（`faiss-cpu`）** — 需要改 `rag/vector_store.py` 实现，避开 chromadb。
3. **升级到 chromadb 2.x** — 等官方修复 hnsw compactor race condition。
