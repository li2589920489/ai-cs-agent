# 启动与部署指南

本项目支持两种启动方式：**本地开发启动**（改代码热重载，适合开发调试）与 **Docker 一键部署**（环境隔离，适合演示与交付）。

两条路线跑的是同一份代码，但**数据互不相通**——这是最容易踩的坑，见 [第 4 节](#4-两种方案的关键差异)。

## 0. 怎么选

| 场景 | 推荐方案 | 理由 |
|---|---|---|
| 改后端/前端代码，要热重载 | **方案 A 本地** | `--reload` / `next dev` 即时生效，无需重建镜像 |
| 本地已有 1300 条真实商品数据 | **方案 A 本地** | 本地 `data/` 是完整数据集（见第 4 节） |
| 给别人演示 / 一条命令交付 | **方案 B Docker** | 环境自包含，不依赖本机 Python/Node |
| 验证部署能力、准备上线 | **方案 B Docker** | 与生产环境同构（nginx 反代 + 多阶段构建） |
| 首次接触项目，只想先跑起来 | **方案 B Docker** | 少一步依赖安装（镜像内已装好） |

## 1. 前置条件

| 依赖 | 版本 | 用途 | 适用范围 |
|---|---|---|---|
| Python | 3.11+（项目 `.venv` 为 3.13） | 后端 | 方案 A |
| Node.js | 18+（项目为 22） | 前端 | 方案 A |
| npm | 随 Node 附带 | 装前端依赖 | 方案 A |
| Docker Desktop | 最新版 | 容器编排 | 方案 B |
| DeepSeek API Key | — | LLM 推理（`deepseek-chat`） | 两者都需要 |

> **API Key 从哪来**：DeepSeek 开放平台申请，形如 `sk-xxxxxxxx`。任意兼容 OpenAI 协议的服务均可，改 `.env` 的 `OPENAI_BASE_URL` 即可。

## 2. 方案 A：本地开发启动

### 2.1 首次准备（只做一次）

```powershell
cd <项目根目录>\python-backend

# 1. 建虚拟环境（项目已有 .venv 则跳过）
python -m venv .venv

# 2. 装后端依赖
.venv\Scripts\python.exe -m pip install -r requirements.txt

# 3. 配置环境变量
#    复制 .env.example 为 .env，填入：
#    OPENAI_API_KEY=sk-xxxx
#    OPENAI_BASE_URL=https://api.deepseek.com/v1
#    DEFAULT_TENANT_API_KEY=tk_xxxx    （知识库写操作鉴权，前端要配同名值）
#    AGENT_API_KEY=ak_xxxx             （坐席工单接口鉴权）
```

前端依赖：

```powershell
cd ..\ui
npm install
```

> 前端鉴权 key 配在 `ui/.env.local`（`NEXT_PUBLIC_TENANT_API_KEY` / `NEXT_PUBLIC_AGENT_API_KEY`），**必须与后端 `.env` 里的值一致**，否则知识库写操作会 403。

### 2.2 日常启动

**方式 1：一条命令（推荐）**

```powershell
cd <项目根目录>\ui
npm run dev
```

`concurrently` 会同时拉起后端（8000）与前端（3000），日志前缀区分。

**方式 2：两个终端分开（排查问题时更清晰）**

```powershell
# 终端 1 —— 后端
cd <项目根目录>\python-backend
.venv\Scripts\python.exe -m uvicorn main:app --reload --host 0.0.0.0 --port 8000

# 终端 2 —— 前端
cd <项目根目录>\ui
npm run dev:next
```

### 2.3 验证

| 检查项 | 地址 | 期望 |
|---|---|---|
| 前端界面 | http://localhost:3000 | 客服对话界面（标题「AI电商客服智能体」） |
| 后端健康 | http://127.0.0.1:8000/health | `{"status":"healthy","service":"AI电商客服智能体","agents":"6"}` |

> 本地开发模式下前端通过 `next.config.mjs` 的 rewrites 把 `/api/*` 转发到 `http://127.0.0.1:8000`，**不需要 nginx**。所以访问入口是 3000 端口，而不是 80。

### 2.4 数据说明

本地数据存放在 `python-backend/data/`：

| 文件/目录 | 内容 | 首次启动是否自动生成 |
|---|---|---|
| `knowledge.db` | 商品知识库（SQLite） | ✅ 自动建表 + 灌 4 条 demo 商品 |
| `chroma_rag/numpy_store.db` | 向量索引（自建 numpy 后端） | ✅ 首次检索时自动构建 |
| `auth.db` | 租户凭据（api_key 哈希） | ✅ 启动时 seed 两个租户 |
| `models/` | BGE 向量模型（本地副本） | ❌ 需手动放置，否则首次运行从 HuggingFace 下载 |
| `eval/` | 评测数据集（含 EcomRetrieval 语料） | ❌ 需手动放置 |

**导入 1300 条真实商品**（可选，让「有什么商品」类问题能答得上）：

```powershell
cd <项目根目录>\python-backend
.venv\Scripts\python.exe scripts\import_real_products.py
```

该脚本从 `data/eval/ecom_retrieval/corpus.parquet`（100902 条真实淘宝商品标题）清洗、分类、配额抽取 1300 条入库。

> **BGE 模型**：`rag/embedding.py` 会先找 `data/models/bge-small-zh-v1.5/`，找到就用本地副本，找不到才联网下载（约 100MB）。国内网络建议提前放好本地副本。

## 3. 方案 B：Docker 一键部署

### 3.1 前置：启动 Docker Desktop

**先启动 Docker Desktop 并等待引擎就绪**（右下角鲸鱼图标变绿）。daemon 未运行时执行任何 docker 命令都会报：

```
failed to connect to the docker API at npipe:////./pipe/dockerDesktopLinuxEngine
```

验证引擎就绪：

```powershell
docker info
# 看到 "Server Version: xx.x.x" 即为就绪
```

### 3.2 构建并启动

```powershell
# 1. 必须切到项目根目录（compose 文件所在处）
cd <项目根目录>

# 2. 确认 python-backend/.env 已填好 OPENAI_API_KEY
#    compose 通过 env_file 自动读取，无需在 shell 里 export

# 3. 构建并启动（首次约 3-5 分钟：拉基础镜像 + 装依赖 + 前端构建）
docker compose up -d --build
```

启动的三个服务：

| 服务 | 镜像 | 作用 | 端口 |
|---|---|---|---|
| `backend` | 本地构建 | FastAPI 后端 | 8000（调试直连） |
| `frontend` | 本地构建 | Next.js standalone | 3000（仅容器内） |
| `nginx` | nginx:1.27-alpine | 统一入口 + 反向代理 | **80** |

### 3.3 验证

```powershell
# 三容器状态（应为 Up / Up (healthy)）
docker compose ps

# 后端（经 nginx 反代）
curl http://localhost/health
# → {"status":"healthy","service":"AI电商客服智能体","agents":"6"}

# 前端
curl http://localhost/
```

浏览器打开 **http://localhost/** 即为客服界面。

### 3.4 常用命令

| 操作 | 命令 |
|---|---|
| 查看状态 | `docker compose ps` |
| 查看日志（全部） | `docker compose logs -f` |
| 只看后端日志 | `docker compose logs -f backend` |
| 重启某服务 | `docker compose restart nginx` |
| 停止（保留数据） | `docker compose down` |
| 停止并清空数据 | `docker compose down -v` |
| 强制重建某服务 | `docker compose up -d --force-recreate nginx` |
| 进容器调试 | `docker compose exec -T backend bash` |

> **PowerShell 提示**：`docker compose up --build` 在 PowerShell 里可能因 docker 的 stderr 进度输出被判为 `NativeCommandError` 而返回非零退出码，**但构建往往已经成功**。判断成败请以容器是否 `Started` / `Up` 为准，不要只看退出码。

### 3.5 数据说明

Docker 使用 **Docker 命名卷 `rag_data`** 挂载到容器内 `/app/data`，与本地 `python-backend/data/` **完全隔离**：

- 容器首次启动只有 4 条 demo 商品 + 自动 seed 的两个租户
- 你在容器里导入的商品，本地看不到；反之亦然
- `python-backend/data/models` 以只读方式 bind mount 进容器（复用本地 BGE 模型，避免镜像臃肿）

**想让 Docker 复用本地数据**，把 `docker-compose.yml` 里 backend 的卷改成 bind mount：

```yaml
volumes:
  - ./python-backend/data:/app/data          # 改为直接挂本地目录（替代 rag_data:/app/data）
  - ./python-backend/data/models:/app/data/models:ro
```

## 4. 两种方案的关键差异

| 维度 | 方案 A 本地 | 方案 B Docker |
|---|---|---|
| **访问地址** | http://localhost:3000 | http://localhost/（80） |
| **`/api` 转发** | Next.js rewrites → `127.0.0.1:8000` | nginx → `backend:8000` |
| **数据位置** | `python-backend/data/`（宿主机目录） | Docker 卷 `rag_data`（容器内） |
| **初始商品数** | 4 条 demo（跑导入脚本可到 1300+） | 4 条 demo |
| **首次启动耗时** | 慢（装依赖 + 下模型） | 慢（拉镜像 + 构建） |
| **后续启动** | 秒级 | 秒级（`docker compose up -d`） |
| **改代码生效** | 热重载，即时 | 需 `--build` 重建镜像 |
| **环境依赖** | 需本机 Python + Node | 只需 Docker Desktop |

> **核心认知**：本地与 Docker 是**两套独立数据库**。排查「导入后搜不到」时，先确认你在哪套环境里操作，以及是否重建了向量索引。

## 5. 故障排查

### 5.1 启动阶段

| 现象 | 原因 | 解决 |
|---|---|---|
| `no configuration file provided: not found` | 不在项目根目录执行 | `cd` 到 `docker-compose.yml` 所在目录 |
| `failed to connect to the docker API at npipe://...` | Docker Desktop 未启动 | 启动 Docker Desktop，等引擎就绪 |
| `docker: command not found` | PATH 未包含 Docker | 重启终端；或在 Docker Desktop 设置中开启 CLI 集成 |
| 端口 80 被占用 | 本机有别的 Web 服务 | 改 `docker-compose.yml` 里 nginx 的 `ports: "8080:80"` |

### 5.2 运行阶段

| 现象 | 原因 | 解决 |
|---|---|---|
| **502 Bad Gateway** | nginx 容器是旧的，缓存了已失效的 backend/frontend IP | `docker compose restart nginx` |
| 前端能开但接口全 404 | 后端未启动（本地模式） | 启动 8000 端口后端 |
| 导入返回 401 | API Key 无效 | 检查 `ui/.env.local` 的 key 与后端 `auth.db` 里种子一致 |
| 导入返回 403 | 写操作缺租户 key | 在 `ui/.env.local` 配 `NEXT_PUBLIC_TENANT_API_KEY` 后重启前端 |
| 坐席接口 403 | key 不是 agent 角色 | 用 `AGENT_API_KEY`（role=agent）而非租户 key |
| **导入成功但对话搜不到** | 向量索引未重建 | 见 [6.3](#63-导入后必做重建向量索引) |
| 首次对话很慢 | BGE 模型首次加载 + 索引构建 | 正常，后续会快 |
| 模型下载失败（本地模式） | 无法访问 HuggingFace | 配置 HF 镜像，或手动放置模型到 `data/models/` |

### 5.3 工具环境问题

| 现象 | 原因 | 解决 |
|---|---|---|
| PowerShell 里 build 返回 exit 1，但容器已 Started | PowerShell 把 docker 的 stderr 进度当错误 | 以容器状态为准，忽略退出码 |
| `docker compose exec` 输出为空 | 未加 `-T`，TTY 分配失败 | 加 `-T`：`docker compose exec -T backend python xxx.py` |
| 容器内 `python -c "import rag"` 报 ModuleNotFound | exec 的 cwd 不在 `/app` | 脚本里加 `sys.path.insert(0, '/app')` |

## 6. 知识库导入流程

### 6.1 导入方式

| 方式 | 入口 | 输入格式 | 是否走 LLM |
|---|---|---|---|
| CSV 批量导入 | 前端知识库面板 → 上传 CSV | 表头支持中英文（见下） | 否，直接结构化入库 |
| 文档导入 | 前端知识库面板 → 上传文档 | `.pdf` / `.docx` / `.txt` | 是，DeepSeek 抽取字段 |

**CSV 表头映射**（中英文均可）：

| 字段 | 可接受的表头 |
|---|---|
| `product_id` | `product_id` / `商品ID` |
| `name` | `name` / `商品名称` / `名称` |
| `description` | `description` / `介绍` / `商品介绍` |
| `selling_points` | `selling_points` / `卖点` |
| `specs` | `specs` / `规格` |
| `faq` | `faq` / `常见问题` / `问答` |
| `category` | `category` / `类目` / `分类` |

> 卖点 / 规格 / FAQ 为多条字段，用**分号**（`;` 或 `；`）或换行分隔。CSV 编码建议 UTF-8（带 BOM 兼容 Excel）。

### 6.2 文档导入的 LLM 抽取

文档导入会用 DeepSeek 提取 `product_id / name / description / selling_points / specs / faq` 六个字段。为获得最好抽取效果，文档建议：

- 每个商品独立成段，标题写明商品名
- 卖点、规格用列表或分句表述
- FAQ 写成「问题：xxx 答案：xxx」的形式

### 6.3 导入后必做：重建向量索引

导入只写入 SQLite 知识库，**向量索引是惰性更新的**——必须重建后，客服对话才能检索到新商品。

**方式 1：前端**——知识库面板点「重建索引」

**方式 2：接口**

```powershell
curl -X POST http://localhost/api/knowledge/reindex `
  -H "x-api-key: <DEFAULT_TENANT_API_KEY>"
```

> 本地模式把 `http://localhost` 换成 `http://127.0.0.1:8000`。

重建成功后可这样验证：在对话里问新导入商品的专属信息，应能命中并给出对应字段内容。

## 7. 路径与端口速查

### 目录

```
ai-cs-agent/
├── docker-compose.yml          # Docker 编排（方案 B 入口）
├── nginx.conf                  # nginx 反向代理配置
├── python-backend/
│   ├── main.py                 # FastAPI 入口
│   ├── auth.py                 # 鉴权（租户/坐席）
│   ├── knowledge_store.py      # 知识库存储
│   ├── .env                    # 环境变量（含 API Key，勿提交）
│   ├── .venv/                  # 虚拟环境（方案 A）
│   ├── data/                   # 本地数据目录（方案 A）
│   └── scripts/
│       └── import_real_products.py   # 1300 条真实商品导入脚本
└── ui/
    ├── package.json            # npm 脚本
    ├── .env.local              # 前端鉴权 key
    ├── next.config.mjs         # rewrites: /api → 127.0.0.1:8000
    └── Dockerfile              # 前端多阶段构建（方案 B）
```

### 端口

| 端口 | 方案 | 服务 |
|---|---|---|
| 3000 | A | 前端 dev server（也是访问入口） |
| 8000 | A / B | 后端 FastAPI（Docker 下也映射出来供调试） |
| 80 | B | nginx 统一入口（访问入口） |

### 关键接口

| 接口 | 方法 | 用途 |
|---|---|---|
| `/health` | GET | 健康检查 |
| `/api/chat` | POST | 客服对话（SSE 流式） |
| `/api/knowledge` | GET / POST | 知识库列表 / 新增 |
| `/api/knowledge/search` | GET | 知识库检索 |
| `/api/knowledge/import` | POST | CSV 批量导入 |
| `/api/knowledge/import-doc` | POST | 文档导入（LLM 抽取） |
| `/api/knowledge/reindex` | POST | 重建向量索引 |
| `/api/escalations` | GET | 人工工单列表（坐席） |
